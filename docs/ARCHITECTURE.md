# 🏗️ ארכיטקטורה — פירוט ה-Workflow

מסמך זה מתאר כל node ב-workflow לפי סדר הזרימה, וכולל צ׳קליסט אבטחה לפני ייצוא.

---

## זרימת הנתונים

```
Schedule Trigger
   └─► Hebcal חגים ─► שער שבת/חג ─► מזג אוויר ─┬─► sport5 ביתר ─────────────┐
                                              ├─► sport5 הפועל ירושלים ─────┤
                                              └─► API-Football טדי ─────────┤
                                                                    מיזוג מקורות
                                                                          │
                                                                 חילוץ משחקי טדי
                                                                          │
                                                              חישוב משחקים עתידיים
                                                                   ┌──────┴──────┐
                                                             נוסח הודעה      ניסוח מייל
                                                                   │             │
                                                              Telegram        Gmail
```

---

## פירוט ה-Nodes

### 1. `Schedule Trigger`
מפעיל את ה-workflow לפי שני ביטויי cron:
- `0 8 * * 0-5` — א׳–ו׳ ב-08:00.
- `30 22 * * 6` — מוצ״ש ב-22:30 (רענון אחרי צאת שבת).

### 2. `Hebcal חגים` (HTTP Request)
מושך את לוח החגים היהודי לחודש הנוכחי מ-Hebcal (`maj=on`, `i=on` ללוח ישראלי).
משמש לזיהוי ימים טובים (yom tov).

### 3. `שער שבת/חג` (Code)
**שער חוסם**: ממיר את התאריך הנוכחי לאזור הזמן `Asia/Jerusalem`, ובונה רשימת
תאריכי חג (`holidayDates`). אם **היום** הוא חג — מחזיר מערך ריק והזרימה נעצרת
(לא נשלחות הודעות בחג). אחרת מעביר הלאה את רשימת תאריכי החג לשימוש בהמשך.

### 4. `מזג אוויר` (HTTP Request)
תחזית שעתית ל-14 יום מ-Open-Meteo עבור קואורדינטות ירושלים
(`lat=31.77, lon=35.19`): טמפרטורה וסיכוי משקעים. `onError: continueRegularOutput`
כדי שכשל בתחזית לא יפיל את כל ה-workflow.

### 5. מקורות המשחקים (3 nodes במקביל)
| Node | מקור | הערה |
|------|------|------|
| `sport5 ביתר` | `sport5.co.il/team.aspx?FolderID=191` | HTML של דף ביתר ירושלים |
| `sport5 הפועל ירושלים` | `sport5.co.il/team.aspx?FolderID=9749` | HTML של דף הפועל ירושלים |
| `API-Football טדי` | `v3.football.api-sports.io/fixtures?venue=866` | כל המשחקים בטדי, כולל גביע/קבוצות אחרות |

שני נודי sport5 שולחים כותרות User-Agent של דפדפן נייד כדי לקבל HTML תקין.
נוד API-Football משתמש ב-**Header Auth credential** (ראה צ׳קליסט אבטחה).

### 6. `מיזוג מקורות` (Merge)
מאחד את שלושת המקורות במצב `append` (3 כניסות).

### 7. `חילוץ משחקי טדי` (Code)
מנרמל את שני סוגי המקורות לפורמט אחיד:
- **API-Football** (JSON): מסנן לפי שם המגרש (`teddy|malcha`), ממפה ליגה לשם אירוע בעברית.
- **sport5** (HTML): פרסור טבלאות, שמירה רק על שורות בהן הקבוצה המארחת היא "טדית"
  (ביתר או הפועל ירושלים), זיהוי דרבי.

הסרת כפילויות לפי מפתח `date|time`. פלט אחיד: `eventName, hostTeam, opponent,
date, time, source`.

### 8. `חישוב משחקים עתידיים` (Code)
הליבה הלוגית. לכל משחק עתידי:
- מחשב רמת דחיפות: 🔴 ≤1 יום, 🟠 ≤4 ימים, 🟢 רחוק יותר.
- קובע אמצעי הגעה: **רכבת** בימי חול, **רכב** בשבת/ערב שבת/חג (רכבת ישראל לא פעילה).
- מחשב שעות: יציאה מהעבודה, רכבת לתפוס, הגעה משוערת לטדי — לפי הקבועים הבאים:

| קבוע | ערך | משמעות |
|------|-----|---------|
| `TRAFFIC_START_HOURS` | 3.5 | שעות לפני המשחק שהעומס מתחיל |
| `SAFETY_BUFFER_MIN` | 30 | מרווח ביטחון |
| `WALK_MIN` | 15 | הליכה לעבודה→תחנה |
| `TRAIN_MIN` | 50 | נסיעת רכבת ת״א→י-ם |
| `BUS_MIN` | 30 | תחנה בי-ם→טדי |

ממיין את התוצאות לפי זמן שריקת הפתיחה.

### 9. `נוסח הודעה` (Code) → `Send a text message` (Telegram)
בונה הודעת טלגרם ב-Markdown: המשחק הקרוב במלואו + עד 2 משחקים נוספים בתקציר.
משלב מזג אוויר וקישור Waze. נשלח ל-`chatId` (אישי).

### 10. `ניסוח מייל` (Code) → `Send a message` (Gmail)
בונה מייל HTML מעוצב (RTL) עם כרטיס לכל משחק. נשלח ל-`sendTo` (אישי).

## Security Checklist

לפני ייצוא/דחיפה של ה-workflow לגיט — ודא שאין דליפת מידע:

- [ ] **מפתחות API / טוקנים** — לא מופיעים בקובץ. שמורים כ-credentials ב-n8n בלבד
      (API-Football, Telegram bot token, Gmail OAuth). נוד ה-export של n8n **לא**
      כולל ערכי credential, רק הפניות.
- [ ] **`chatId` בטלגרם** — מוחלף ב-`YOUR_TELEGRAM_CHAT_ID`.
- [ ] **`sendTo` ב-Gmail** — מוחלף ב-`your-email@example.com`.
- [ ] **`webhookId`** — הוסר מנודי Telegram/Gmail (מזהה פנימי, לא נדרש לייבוא).
- [ ] **כתובות/קואורדינטות** — של אצטדיון טדי בלבד (ציבורי), לא של בית/עבודה.
- [ ] לאחר הניקוי, מומלץ להריץ סורק סודות (למשל `gitleaks`) על הריפו.

> 💡 הערך `venue=866`, ה-`FolderID`-ים של sport5, וקואורדינטות טדי אינם רגישים.
